The Loop Is the Moat

An engineer's autopsy of a $10B agent — rebuilt on AWS, incident by incident.

Alam Ahmed — Cloud Engineer · AWS Community Builder (Dev-Tools) · NOC survivor

In August 2026, a user disconnected her Gmail from Instinct. Instinct kept reading it.

That's the whole article, really. The rest is engineering.

But let me back up. Instinct raised $250M at a $2.5B valuation in August 2026. Three weeks later: $1B at $10B. No app. You text it; it drives a persistent cloud desktop with a virtual mouse, as you. By September it had also leaked a verification code to a prompt-injection test and sent an email without asking.

Everyone wants to talk about the valuation. I want to talk about the loop — the actual engineering — because that's where every incident was born, and where the moat actually is.

The incident log reads like a scandal. I read it as a spec.

00 / the threat model, because their incident report wrote it

$ cat THREAT_MODEL.md
# each incident = one threat = one design constraint.

T1  retained access after revocation
    root cause: the agent bulk-indexed your data into ITS store.
      revoking the OAuth pipe does not purge the index. ever.
    constraint: the agent may cache pointers, never payloads.

T2  prompt injection via untrusted content
    root cause: an agent that reads email will obey email.
      OWASP: this cannot be reliably prevented at the model layer.
    constraint: assume phished. contain, don't prevent.

T3  unauthorised consequential action
    root cause: nothing in the loop distinguished
      "draft" from "sent". confidence is not consent.
    constraint: consequence classification is a control plane,
      not a vibe.

T4  bot detection & tos warfare
    root cause: gui-mimicry is an arms race; resy banned the human.
    constraint: accept as unsolved. prefer official APIs. be honest.

T5  liability capped at $100
    their terms. decision: own the account, the ledger,
    the blast radius.

01 / the loop — where the money and the risk actually live

$ cat loop.py
while not task.done:
    screen  = desktop.screenshot()            # ~1.5–3k tokens, VLM
    a11y    = browser.accessibility_tree()    # cheaper than pixels
    state   = planner.think(screen, a11y, memory.recall())
    action  = state.next_action               # click / type / scroll / call
    desktop.execute(action)
    ledger.append(screen, action)             # every step, replayable

Three engineering realities nobody puts in the launch post:

Speed is a context-window problem, not a compute problem. A 20-minute task is ~150 loop iterations. Naive: you feed the full history back in every step, and cost and latency grow quadratically. You must compress: keep raw frames in the ledger, feed the model a rolling summary plus the last N frames. This is why the agent is "slow." It is not thinking slowly. It is deciding what to remember.

The desktop is not the bill. The loop is the bill. 150 steps × ~3.5k tokens ≈ 0.5M tokens per nontrivial task. At blended frontier prices that's ~$1.50–4 per task. The EC2 underneath? Five cents. The m8g.xlarge is a rounding error; the reason Instinct needs a billion dollars of compute is that the loop runs 150 times per task, millions of tasks per month, and the model does the driving.

Determinism is dead; replay is the replacement. Same task, twice → different paths (see the failure log, §07). So you record everything and make "show me exactly what it saw" a first-class query. The ledger is not compliance. It is the only debugger an agent has.

# how it drives:
#   CDP when the page allows it — deterministic selectors,
#   network introspection. pure visual grounding when it doesn't.

#   vision gives you coverage of every legacy app on earth.

$ agentctl session export
# if this file leaks, an attacker IS you on 40 websites.
# so: the cookie jar never leaves the sandbox volume,
# is snapshotted encrypted, and the export command
# requires the human gate. T2 dies here too — an injected
# agent can click, but it cannot walk away with the jar.

The hot-takes miss this: Instinct's "vault of passwords" is almost the wrong thing to fear. A modern site's session cookie plus the browser fingerprint is the same power with fewer tripwires. Securing the agent means securing the accumulated state of being a person on the internet — which is why the sandbox and the checkpoints matter more than the password manager.

03 / the sandbox — because the agent visits hostile territory

$ cat sandbox.md
# the agent reads attacker-controlled content (T2) and visits
# attacker-controlled sites (malvertising, drive-by). it is,
# at times, a compromised browser. treat the whole desktop as
# untrusted compute:

- firecracker-class microvm per task, not per user.
      the booking agent that just read a phishing email does not
      share a kernel with the agent holding your cookie jar.
- snapshot/rollback: checkpoint the disk before any irreversible
      action. "booked the wrong train. twice." becomes a restore,
      not a phone call to a refund line.
- no clipboard bridge, no shared mounts with the orchestrator.
      the loop executes actions; it cannot reach the ledger
      database. exfil needs two separate compromises.
- egress: FQDN allow-list via network firewall. the single
      highest-value control in the build. twenty minutes.
      every exfiltration path in the incident log drives
      down this road.

04 / capabilities, not credentials — and a tripwire

$ cat capabilities.md
# instinct's model: vault of passwords, one mega-session.
# the failure mode: an injected instruction inherits EVERYTHING.
#
# better model: short-lived, attenuated, single-purpose tokens.
# biscuit/macaroon-style — a capability that can only be
# weakened, never widened, as it passes down:

capability = {
  scope:     "resy.com:book",
  max_spend: "£150",
  expires:   "task-end",
  caveat:    "requires human token for consequence=irreversible"
}

# the agent never holds "your resy login". it holds a token
# that can book one table, once, under £150, that dies when
# the task ends. prompt injection against this inherits a
# coupon, not your identity.
$ cat honeytoken.sh
# tripwire, shamelessly stolen from detection engineering:
# plant a FAKE 2FA code in the agent's inbox — a code that
# exists nowhere else in the universe.
# if ANYTHING ever presents that code anywhere, you do not
# have a bug report. you have a live compromise, with the
# exact session id in cloudtrail.

# this is my answer to c41aa9e in the failure log (§07):
# the agent tried to use a code it read. with a honeytoken,
# that attempt IS the alarm — no user has to notice first.

05 / the gate

$ cat gate.asl.json
{ "StartAt": "Classify", "States": {
    "Classify": { "Type": "Choice",
      "Choices": [
        { "Variable": "$.consequence", "StringEquals": "reversible", "Next": "Execute" }],
      "Default": "Approve" },
    "Approve": { "Type": "Task",
      "Resource": "arn:aws:states:::lambda:invoke.waitForTaskToken",
      "TimeoutSeconds": 3600,
      "Catch": [{ "ErrorEquals": ["States.Timeout"], "Next": "Denied" }],
      "Next": "Execute" },
    "Denied": { "Type": "Fail", "Error": "SilenceIsNotConsent" } } }

Instinct reads a thumbs-up iMessage reaction as approval. Mine: a task token. Reply, or an hour of silence resolves to Denied — logged. "It sent an email without checking" is not a model failure. It is the absence of this state machine.

06 / memory — the moat, and the wound

$ cat memory/README.md
# the thing that makes it an employee and not a chatbot.
# two stores, deliberately separated:

episodic/    what happened: task ledger, replay index.
             append-only, per-session, TTL'd.
             poisonable? yes — injected "memories".
             mitigated: episodic memory can cost you a task,
             never a credential.

semantic/    who you are: preferences, facts, relationships.
             this is T1's home. instinct's disconnect incident
             lived here: the index outlived the integration.
             my constraint, which i will defend in a code review:
             semantic memory stores derived facts with
             provenance + TTL. every entry answers
             "where did i learn this, and when does it expire?"
             revocation deletes the source AND the derivations.
             if your memory design can't survive a disconnect
             test, you don't have memory. you have a liability.

Unresolved: memory is also where the product value is. The tension between "remembers you forever" and "forgets on command" is the actual hard problem of this entire class. Anyone who tells you it's solved is selling the demo.
